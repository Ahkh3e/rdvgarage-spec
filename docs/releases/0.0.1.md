# Release 0.0.1

Smallest usable slice: join by invite, get an account, join a crew, go live on the map, see this week's top speed leaderboard. Modules can be added or removed without a rewrite.

## In scope

| Module | Scope in 0.0.1 | Spec |
|---|---|---|
| App shell | Cross-platform app, iPhone first, tabs, module registry, flags | features/app-shell.md |
| Referral | Share invite (24 hours, no limits), revoke, who-joined list, expired page, signup gated by invite, referral chain | features/invites.md |
| Accounts | Register by invite with handle, email, and password; email confirmation, password reset and change; devices; edit profile; delete account; disclaimers acceptance; operator tools | features/accounts.md |

Supporting docs: `docs/architecture.md`, `docs/data-model.md`, `docs/api.md`, `docs/design.md`, `docs/disclaimers.md`.

## Out of scope

RDVs, maps handoff, notifications, stats and streaks, car profiles, galleries, convoy, minigames, admin role, crew admin tools, abuse tooling, admin UI, report and block, previous-week leaderboard, data export, store submission (noted in `docs/store-submission.md`).

## Modular by design

- Each feature is a self-contained module: its own UI, state, and data access. Modules do not import each other.
- Modules talk through the core contracts (Session, CrewContext, LocationStream, Events, Backend), defined in `docs/features/app-shell.md`.
- Modules register themselves with the shell and sit behind flags. Adding a module adds one entry to the app's module list; removing it deletes that entry.
- The leaderboard reads live data and holds none of its own. Live location does not know the leaderboard exists. A future stats module can read the same data.
- Backend mirrors this: one schema per module, shared only by identity and crew membership (`docs/architecture.md`).

### App structure

- React Native with Expo, TypeScript. One workspace package per module: core, referral, accounts, crews, map, live-location, leaderboard, plus the app that wires them.
- Platform-specific code stays inside a module behind its own interface, so Android adds files, not rewrites.
- Dependencies are injected through the core contracts, never through singletons.

## Acceptance

Accounts and invites
- A user opens an invite link, fills the account form (handle, email, password), accepts the disclaimers, confirms being 18 or older, confirms the email, signs in, and lands on My Crews.
- Registration without a valid invite fails and creates no account.
- An expired, revoked, or disabled invite shows the expired page.
- A member can create invites without limit and see who joined through each.
- A user who forgot their password resets it by email, and other devices are signed out.
- A user can revoke another device from Devices.
- Deleting an account removes the user's data and keeps the referral chain; an owned crew passes to another member or is dissolved.

Crews and live
- A user creates a crew and shares its link; a second user joins.
- Both select the crew, go live, and see each other moving on the map.
- Stopping removes the user from the map for others immediately.
- A user who did not share a session with a crew never appears in that crew's map or leaderboard.

Leaderboard
- The Board lists both with this week's top speeds in km/h, ranked, with the disclaimer footer.
- A session crossing Monday 00:00 Toronto time is counted per week without carrying over its max.
- Disabling the leaderboard flag removes it with no other module affected.

Production checks
- In production mode, `register` sends the confirmation email and sign-in is refused until the email is confirmed.
- Before release, verify `AUTO_CONFIRM_EMAIL` is off and the production project is named `production`.
- Resend confirmation and the 24-hour expiry of unconfirmed accounts work in production mode.

Safety wording
- Disclaimers appear at onboarding, on the Go live sheet, and on the Board footer.

## Test plan

- Background location on a real iPhone and a real Android phone: foreground, background, screen locked, app swiped away, permission revoked. Check stale-session ending after 5 minutes.
- Realtime: two to five devices in one crew; check message volume against the free tier.
- Privacy: confirm access policies with a non-member and a member of a different crew trying to read profiles, sessions, and segments.
- Link flows: invite links opened with the app installed and not installed, on both platforms, including expired links.
- Account emails: confirmation and password reset delivered through the chosen SMTP provider (production mode). Playthroughs of the rest of the app use test mode.
- Week boundary: set the clock or seed segments around Monday 00:00 Toronto time.
- Delete account with an owned crew, with and without other members.
